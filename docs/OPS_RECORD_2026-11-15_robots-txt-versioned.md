# Ops record 2026-11-15 — the live robots.txt is now versioned and tested

**Nothing was installed or changed on any server.** Read-only work.

The file that answers `https://www.poolrentalnearme.com/robots.txt` is a static file
served by nginx on WEST (Last-Modified 2026-08-08). It was in no repository. It is
now in `ops/west/robots/`, byte for byte, together with:

- the six ccTLD robots files (generated by fresh-web), for the record;
- a dependency-free matcher that follows Google's documented rules, with unit tests
  against the examples in that documentation;
- tests that state what the live file does today, with its defects labelled as such;
- a proposed replacement (`robots.www.poolrentalnearme.com.proposed.txt`) with six
  small edits, tests of its intended behaviour, and a check that every URL in the
  sitemaps is allowed;
- a comparison with what `server/resources/robotsTxt.js` and the fresh-web generator
  would produce (neither produces the live file);
- an install / roll-back runbook.

Everything, including the evidence for each finding and the questions that need
Derek's decision, is in `ops/west/robots/README.md`.

Run the tests: `node --test ops/west/robots/*.test.mjs` (no `node_modules` needed).

What was found, in short:

- `Disallow: /host/preview/` binds only to CCBot (it sits after the last
  `User-agent` line).
- `Disallow: /p/p/` hides a 301 from crawlers.
- `Disallow: /s?*&page=` hides `noindex, follow` responses, and does not cover
  `/s?page=N`. Left as it is in the proposed file pending Search Console data.
- Twelve named crawlers have their own `Allow: /` group, so none of the private-URL
  rules apply to them.
- `/l/new`, `/auth`, `/sale` and `/order` are prefix rules that would swallow a
  listing titled "New …", `/author/…`, `/salem` and the like. No such URL is live today.
- Signed-in routes (`/account`, `/inbox`, `/profile-settings`, listing edit and
  checkout, …) answer 200 with an empty page and no noindex when signed out, and
  `/reset-password` answers `index, follow`; robots.txt is their only protection.
- On the ccTLDs, `/sitemap-country.xml` is disallowed by the same file that names it
  as the sitemap. That is in fresh-web; not changed here.
- No URL in today's sitemaps is blocked by the live file.
